sel4-lean > overview > walk > w2

seL4 is an operating-system kernel with a machine-checked proof, in Isabelle/HOL, that its C code does what its specification says. This project is moving that proof to Lean 4, one stage at a time. Stages C0–C3 are done: the original Isabelle proofs pass on our own machine, Lean has l4v’s monad, Hoare logic and corres, the first slice of the kernel model is translated from Haskell into Lean by our own tool, and the first refinement lemma, cancelSignal_corres, is proved in Lean over that generated code.

the proof stack · what l4v proves

  Abstract spec      hand-written Isabelle
        ▲
        │  Refine     5,325 lemmas + invariants (AInvs)
        │
  Executable spec    Haskell model
        ▲            │ haskell-translator (Python)
        │            ▼
        │          Isabelle text   (spec/design)
        │
        │  CRefine
        │
  C implementation   C-parser → Simpl → AutoCorres

Each arrow is a refinement proof: every behaviour of the lower layer is allowed by the layer above. Chained together, they show the C code meets the abstract spec.

porting plan · three pieces

1. definitions

Haskell → Lean for the executable spec. Isabelle → Lean for the abstract spec. This is the step from HOL to dependent types: HOL's 'a word becomes BitVec n, HOL's always-inhabited types need Inhabited instances, and locales become sections.

2. proof machinery

l4v's nondeterministic state monad, the wp calculus, corres, and the automation the proofs depend on: wpsimp, crunch (629 uses in Refine alone).

3. proofs

Either translate them (Isabelle → Dedukti → Lean) or re-prove them in Lean with AI help. Crawl measures both on a small slice, then we choose.

one function, three forms · cancelSignal, the first crawl target

Haskell model · Notification.lhs

cancelSignal threadPtr ntfnPtr = do
  ntfn <- getNotification ntfnPtr
  assert (isWaiting (ntfnObj ntfn))
    "must be waiting"
  let queue' = delete threadPtr
        $ ntfnQueue $ ntfnObj ntfn
  ntfn' <- case queue' of
    [] -> return $ IdleNtfn
    _  -> return $ (ntfnObj ntfn)
            { ntfnQueue = queue' }
  setNotification ntfnPtr
    (ntfn { ntfnObj = ntfn' })
  setThreadState Inactive threadPtr

The translator's job is almost purely syntactic, and Lean already has do, where, { s with f := v } and as-patterns. Most of the translator's 2,352 lines of hand-written case rewrites exist to work around Isabelle and should disappear for Lean. The lemma that ties the left and right columns together, cancelSignal_corres, is about 35 lines of apply steps: corres_split, wp, corres_guard_imp. That's the shape of what C2 has to rebuild.

the lean side · c2, ported from l4v lib/Monads and Corres_UL

the monad · Monad/Nondet.lean

-- l4v: 's ⇒ ('a × 's) set × bool
def NondetM (σ α : Type) :=
  σ → ((α × σ) → Prop) × Prop

instance : Monad (NondetM σ) where
  pure := ret
  bind := bind

def incr : NondetM Nat Unit := do
  let x ← get
  put (x + 1)

hoare logic · Monad/VCG.lean

def valid (P : σ → Prop) (f : NondetM σ α)
    (Q : α → σ → Prop) : Prop :=
  ∀ s, P s → ∀ r s',
    (f s).1 (r, s') → Q r s'

example :
    ⟪fun _ => True⟫ incr
    ⟪fun _ s => s > 0⟫ := by
  unfold incr; wpsimp

refinement · Corres.lean

theorem corres_split
  (hx : corres sr nf nf' r' P P' a c)
  (hy : ∀ rv rv', r' rv rv' →
     corres sr nf nf' r (R rv) (R' rv')
            (b rv) (d rv'))
  (ha : ⟪Q⟫ a ⟪R⟫)
  (hc : ⟪Q'⟫ c ⟪R'⟫) :
  corres sr nf nf' r (P ∧ Q) (P' ∧ Q')
    (a >>= b) (c >>= d)

Because NondetM is a Lean Monad, ordinary do-notation now means l4v’s nondeterministic do … od. Translated Haskell can keep its original shape. Isabelle needed the translator to produce that syntax; Lean gets it free. The corres statement above is abbreviated from corresUnderlying.

c3: generated lean · the two sides C4 must connect

executable spec · Exec/Gen/Notification.lean · generated by hs2lean, unedited

def cancelSignal (threadPtr : PPtr TCB) (ntfnPtr : PPtr Notification) : Kernel Unit :=
  let isWaiting := fun ntfn => match ntfn with
    | NTFN.WaitingNtfn .. => true
    | _ => false
  do
    let ntfn ← getNotification ntfnPtr
    assertH (isWaiting (Notification.ntfnObj ntfn)) "cancelSignal: notification object must be waiting"
    let queue' := deleteH threadPtr (NTFN.ntfnQueue (Notification.ntfnObj ntfn))
    let ntfn' ← match queue' with
      | [] => pure NTFN.IdleNtfn
      | _ => pure (NTFN.set_ntfnQueue (Notification.ntfnObj ntfn) queue')
    setNotification ntfnPtr ({ ntfn with ntfnObj := ntfn' })
    setThreadState ThreadState.Inactive threadPtr

abstract spec · Abstract/IpcCancel.lean · hand-translated from IpcCancel_A.thy

def cancel_signal (threadptr ntfnptr : ObjRef) : SMonad Unit := do
  let ntfn ← get_notification ntfnptr
  let queue ← (match ntfn.ntfn_obj with
    | .WaitingNtfn queue => pure queue
    | _ => NondetM.fail)
  let queue' ← pure (queue.erase threadptr)
  let newNTFN ← pure (ntfn_set_obj ntfn (match queue' with
    | [] => .IdleNtfn
    | _ => .WaitingNtfn queue'))
  set_notification ntfnptr newNTFN
  set_thread_state threadptr .Inactive

The translator keeps the Haskell structure: do stays do, where becomes let, record updates become { x with … }. Everything outside the slice (setThreadState, the object heap, the kernel state) is an opaque stub. C4 assumes the l4v lemmas about those as hypotheses, just as cancelSignal_corres in l4v uses lemmas proved in other files.

It works, and it’s the only route that carries Isabelle’s actual proofs. It doesn’t scale to seL4: the exporter’s own measurements reach 1 GB of proof terms at HOL.Set_Interval, nothing past HOL.List has been translated, and l4v sits on HOL-Main, HOL-Library and Word_Lib before its million lines even start. The exported theorems also live in an embedding of HOL. Using them from Lean needs a bridge from HOL’s bool to Lean’s Prop.

Modelling follows l4v’s Isabelle where it can: Kernel is NondetM KernelState, maps and arrays are functions, sets are predicates, Haskell Int is Nat, Word is BitVec 64. One temporary compromise: self-recursive functions are partial, which hides their bodies from proofs, until W4 adds termination proofs.

lessons · from c0

  • Check the disk first. A 32-core box spent 7 minutes on a Docker build because it was writing to network disk.
  • Isabelle caps sessions at 8 threads unless you set threads in the user settings, since some tests bypass the Makefile.
  • l4v's timeouts count CPU time. More threads use the budget faster, so scale the timeouts with the thread count.
  • Proof structure limits parallelism. Big sessions average 8–11 cores busy because the theories form long import chains. A Lean port's module layout will face the same limit.
  • Lean surface syntax caused every C2 build failure. Keywords (unless, assert), notation precedence and cases renaming broke builds; l4v’s semantics never did.
  • Lean’s do hides join points. let x ← match … becomes a local function plus a match, so proof automation has to see through it.
  • “It compiles” is not “it’s right”. Dropped guards and over-eager partial both compiled cleanly; only audits and tests caught them.
  • A spike can succeed and still say no. The Dedukti route works end to end, but the numbers rule it out for l4v at today’s scale.
  • Rootless Docker makes the upstream per-user image unnecessary, because container root is already you.
